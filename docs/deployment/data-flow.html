Image Generation — Request Lifecycle

Read left to right: where each message comes from and where it goes
🌐 User Browser ☁️ CloudFront λ Web Lambda 🐘 PostgreSQL 📬 SQS ⚙️ Worker Lambda 🤖 AI Provider 🗄️ S3
Phase 1 — Create Generation
1
🌐 User → ☁️ CloudFront → λ Web Lambda
User clicks Generate. Browser sends POST /api/generations with prompt, brand settings, output format, and mode. CloudFront forwards the request to Web Lambda via its response-streaming Function URL.
POST /api/generationsresponse streaming
2
λ Web Lambda → 🐘 PostgreSQL
Web Lambda validates the request (auth via Clerk JWT, credit balance check via Ledger). Then inserts a generation row with status=queued and one generation_variant row per requested variant (each variant = one AI image call). Credits are reserved at this point via Ledger.reserve().
INSERT generationsINSERT generation_variantsLedger.reserve()
3
λ Web Lambda → 📬 SQS Generations
For each variant, Web Lambda sends one SQS message: { generationId, variantId, workspaceId }. Messages are independent — each variant is processed by a separate Worker Lambda invocation.
SQS SendMessage ×N variantsbatchSize=1
4
λ Web Lambda → ☁️ CloudFront → 🌐 User
Web Lambda returns HTTP 201 with the new generationId. The browser receives this immediately — the actual image generation happens asynchronously in the background.
HTTP 201 { generationId: "gen_abc123" }
Phase 2 — Polling While Worker Runs
5
🌐 User → polls every ~2s → λ Web Lambda → 🐘 PostgreSQL
Browser polls GET /api/generations/{id} every ~2 seconds. Web Lambda reads the generation status from DB. While the worker is still running, it returns status: "queued" or status: "processing".
HTTP 200 { status: "queued" | "processing" }
GET /api/generations/:idpolling
Phase 3 — Worker Lambda Processes the Job
6
📬 SQS → SqsEventSource trigger → ⚙️ Worker Lambda
SQS triggers Worker Lambda (batchSize=1, one message per invocation). The visibility timeout is 180s — the message is hidden from other consumers while the worker processes it. Worker Lambda timeout is 120s, giving a 60s buffer before SQS re-delivers.
SqsEventSourcevisibility 180stimeout 120s
7
⚙️ Worker → 🐘 PostgreSQL
Worker loads the variant, generation, brand, template, and mood from DB. Updates variant status to running. Builds the AI prompt (Quick Create mode or Legacy mode). Moderates the prompt text before any AI call.
status → runningbuildPrompt()moderateText() — blocks if flagged
8
⚙️ Worker → generateImage() → 🤖 AI Provider → image bytes → ⚙️ Worker
Worker calls the AI provider (OpenAI DALL-E 3, Replicate, or Recraft depending on the template's preferredModel). On failure, retries once with the same provider, then falls back to AWS Bedrock SD3.5. AI returns raw PNG bytes.
retry ×1Bedrock fallbackprovider.latency_ms metric
9
⚙️ Worker → moderateImage() → ⚙️ Worker
After receiving the image bytes, Worker moderates the generated image. If the image is flagged as unsafe → marks variant failed_safety, releases credits, stops processing. The image is never written to S3.
moderateImage() — blocks if flaggedimage never stored if flagged
10
⚙️ Worker → 🗄️ S3
Worker uploads the raw AI-generated PNG as the background. Key pattern: workspaces/{id}/gen/{id}/variant/{id}/background.png. Preserves the unprocessed image separately from the final rendered output.
PUT background.pngkeys.generationBackground()
11
⚙️ Worker → render() → ⚙️ Worker
Worker renders the template overlay onto the background: brand palette, fonts, logo, mood decorations/colors, text slots (headline, subhead, CTA). Uses Satori for most templates (fast, no browser). Switches to Puppeteer/Chromium for complex templates flagged requiresBrowserRender=true.
@layertone/rendererSatori (fast path)Puppeteer/Chromium (complex templates)
12
⚙️ Worker → 🗄️ S3
Worker uploads the final rendered PNG. Key: workspaces/{id}/gen/{id}/variant/{id}/output.png. This is the file that will be presigned and delivered to the user.
PUT output.pngkeys.generationVariant()
13
⚙️ Worker → 🐘 PostgreSQL
Worker commits the generation: (a) Ledger.commit() — converts the reserved credits to a permanent debit; (b) UPDATE variant row to completed with outputS3Key, backgroundS3Key, modelUsed, renderMs; (c) Fan-in — UPDATE parent generation to completed if all variants are terminal.
Ledger.commit()variant → completedgeneration fan-in
Phase 4 — Delivery to User
14
🌐 User → next poll → λ Web Lambda → 🐘 PostgreSQL
Browser's next poll hits the API. Web Lambda reads the generation: status is now completed. Web Lambda calls S3 to generate presigned URLs for each variant's output PNG (time-limited download URLs, typically 1 hour).
status: "completed"S3 presign URLs
15
λ Web Lambda → ☁️ CloudFront → 🌐 User
Web Lambda returns the generation with variant presigned URLs. Browser displays the generated images. User can download or share them directly via the presigned S3 URLs.
HTTP 200 { status: "completed", variants: [{ presignedUrl, modelUsed, ... }] }

Worker Pipeline — Internal Steps

10 steps inside the Worker Lambda, each with its own failure/success path
⚡ Initialisation & Idempotency
🔍
1 · Idempotency check
Load variant from DB. If already completed / failed / failed_safety → return immediately. Prevents SQS at-least-once delivery from re-processing a finished job.
📋
2 · Load full generation context
Read generation, brand (palette, fonts, voice notes, logo assets), template (JSX source, textSafeZones, preferredModel, requiresBrowserRender), and mood (promptModifiers, negativePrompts, decorationTags, accentPalette).
🧠 Prompt Construction
🔗
3 · Brand grounding via pgvector
Embed the generation brief. Use pgvector cosine similarity (<=>) to find top-3 most relevant brand assets. These become image references for the AI (weight: 0.4). Best-effort — failures are silently ignored.
🎨
4 · Build AI prompt
Quick Create mode (commercial.mode = "quick"): uses buildQuickCreatePrompt() from prompt-templates — structured prompt with overlay slots (headline, subtitle, CTA). Legacy mode: concatenates brief + campaign fields + product refs + mood modifiers.
🛡️ Safety
⚠️
5 · Pre-flight text moderation
Moderate the assembled prompt text before calling AI. If flagged → variant failed_safety, credits released, Lambda exits success (message deleted). No AI call is made.
🤖 AI Generation
⚡
6 · Generate image with retry + fallback
Call AI provider with prompt + image references. Attempt 1: primary provider. Attempt 2: same provider retry. Attempt 3 (if configured): Bedrock SD3.5 fallback (without image references). All attempts fail → variant failed, credits released, error sent to Sentry.
🔬
7 · Post-flight image moderation
Moderate the generated image bytes. If flagged → variant failed_safety, credits released. Image never stored in S3. Prevents harmful AI-generated content from reaching storage or users.
🖼️ Rendering & Storage
🗄️
8 · Upload background PNG to S3
Store raw AI output at workspaces/{ws}/gen/{gen}/variant/{var}/background.png. Preserved separately from the rendered output for future use (re-rendering with new templates, quality inspection).
✨
9 · Render template overlay
Composite brand palette, fonts, logo, mood decorations, and text overlay slots onto the background via @layertone/renderer. Uses Satori (SVG→PNG, no browser, fast) for most templates. Switches to Puppeteer/Chromium only when requiresBrowserRender=true.
💳 Commit & Complete
💳
10 · Commit credits + fan-in generation
Ledger.commit() with idempotency key converts reserved credits to permanent debit. Update variant to completed with output keys + metrics. Fan-in: if all variants are terminal, update parent generation status to completed or failed.

Error & Failure Paths

How each failure mode is handled — credits are always released or committed, never lost

⚠️ Text moderation flag

Variant → failed_safety. Ledger.release() refunds reserved credits. Message deleted from SQS (Lambda exits cleanly). No AI call is made.

💥 AI provider failure (all retries)

Retry same provider once → fallback to Bedrock. If all three fail: variant → failed, credits released, exception sent to Sentry with model code and variant ID.

⚠️ Image moderation flag

Generated image bytes discarded. Variant → failed_safety, credits released. Image never stored in S3 or shown to users.

🔧 Template not found

Variant → failed reason template_not_found. Credits released. Happens when a template is deleted after a generation was queued.

⏱️ Lambda timeout (120s)

SQS visibility timeout is 180s. After Lambda times out, SQS waits 60s then re-delivers. Up to 3 receive counts before DLQ. The idempotency check at step 1 prevents double-processing.

📨 Dead Letter Queue

After 3 failed receive attempts, message moves to DLQ (14-day retention). Ops can inspect the raw message in AWS console and replay it once the root cause is fixed.

Caption Generation Flow

Social-media caption jobs are processed by the same Worker Lambda via a separate SQS queue
1
📬 SQS Captions→ SqsEventSource →⚙️ Worker Lambda
The layertone-{stage}-captions queue fires the same Worker Lambda. Message: { jobId, workspaceId }. Worker routes to CaptionWorker.handle().
2
⚙️ Worker→🐘 DB
Load caption job. Idempotency: if already completed / failed → return. Otherwise UPDATE status to running.
3
⚙️ Worker→ generateText() →🤖 OpenAI Text
Call generateText() with system prompt for social-media captions + job's brief + voice instructions. Max tokens: short=80, medium=200, long=500. Returns markdown caption text.

⚙️ Worker→🐘 DB
