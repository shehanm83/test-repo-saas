Service Details

Docker Compose services with healthchecks and persistent volumes

🐘 PostgreSQL (pgvector:pg16)

  • User: layertone / Pass: dev
  • Database: layertone
  • Port: 5432
  • pgvector extension for brand asset embeddings
  • Healthcheck: pg_isready every 5s
  • Volume: pgdata (persistent)

🪣 MinIO (S3-compatible)

  • Root user: minio / Pass: minio12345
  • API Port: 9000
  • Console UI: 9001
  • S3-compatible — same SDK as AWS
  • Volume: miniodata (persistent)
  • Healthcheck: curl /minio/health/live

📬 ElasticMQ (SQS-compatible)

  • SQS API Port: 9324
  • Management UI: 9325
  • In-memory — resets on container restart
  • Queues bootstrap via queue:bootstrap script
  • Generations queue + Captions queue + DLQ

📧 Mailpit (SMTP trap)

  • SMTP Port: 1025
  • Web UI: 8025
  • Catches all outgoing emails
  • No emails delivered externally
  • Useful for Clerk auth emails in dev

Quick Start

Get the full local environment running in under 5 minutes
1

Start Docker Compose infrastructure

Starts PostgreSQL, MinIO, ElasticMQ, and Mailpit. Wait for healthchecks to pass before continuing.

docker compose up -d
2

Install dependencies

pnpm workspace installs all packages across the monorepo.

pnpm install
3

Run database migrations

Applies Drizzle ORM migrations to the local PostgreSQL instance.

pnpm --filter @layertone/db db:migrate
4

Bootstrap queues and storage buckets

Creates SQS queues in ElasticMQ and S3 buckets in MinIO with the correct configuration.

pnpm run queue:bootstrap
pnpm run storage:bootstrap
5

Configure environment variables

Copy .env.example to .env.local (web) and apps/worker/.env (worker). Set AI_MODE=mock and QUEUE_MODE=elasticmq for offline development.

cp .env.example apps/web/.env.local
cp .env.example apps/worker/.env
6

Start dev servers

Run in separate terminals or use a process manager. The web server starts on :3000, worker begins polling ElasticMQ.

# Terminal 1
pnpm --filter @layertone/web dev

# Terminal 2
pnpm --filter @layertone/worker dev

Mock AI Provider

Zero-cost offline image generation for UI and pipeline testing
Feature Behavior in mock mode
Image generation Returns a sample PNG from sample_images/ directory after a configurable delay
Text generation (captions) Returns a hardcoded caption string immediately
Text embeddings Returns a random unit vector (brand grounding is skipped gracefully)
Content moderation Always returns flagged: false — all content passes
Simulated latency Configurable delay (default 2s) to simulate real AI response times
Provider selection Set via AI_MODE=mock in worker .env — wired via MockImageProvider
